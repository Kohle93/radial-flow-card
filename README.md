# Radial Flow Card

[![hacs][hacs-badge]][hacs-url]
[![release][release-badge]][release-url]
[![license][license-badge]](https://github.com/Kohle93/radial-flow-card/blob/main/LICENSE)

Energy flow card for Home Assistant with a radial layout: a hub in the center,
all nodes on a ring around it, animated dots on the spokes. Standalone card
without dependencies, without a build step, with a complete editor.

<img src="https://raw.githubusercontent.com/Kohle93/radial-flow-card/main/docs/images/hero.png" width="420" alt="Radial energy flow card">

## At a glance

- Any number of consumers, order can be changed in the editor
- Partial rings show the share of a defined maximum power
- One dot per line with a tail, speed depends on the power
- Choreography: first the generation flows to the center, then all other lines
- Tap, hold and double tap per node, e.g. to navigate to a sub-dashboard
- Separate sensors for import/export and charge/discharge are supported
- State of charge per consumer, e.g. the car at the wallbox: as a battery icon or as an inner ring
- Own icon set for heat pumps and heating
- Optional weather in the top corner: current temperature with a colored, animated weather icon
- Complete configuration editor in the same style as Status Summary Card, Trash Card Plus and EV Charge Card, YAML optional
- Background, transparency, glass effect, border and shadow freely configurable – same design system as the other cards
- Bilingual: editor and card texts in German when Home Assistant runs in German, otherwise in English

## Installation

### Via HACS

1. Open HACS, three-dot menu, *Custom repositories*
2. Enter this repository URL, category *Dashboard*
3. Install *Radial Flow Card*
4. Clear your browser cache

### Manual

1. Copy `dist/radial-flow-card.js` to `/config/www/radial-flow-card.js`
2. Settings → Dashboards → Resources → Add resource
   - URL `/local/radial-flow-card.js`
   - Type **JavaScript module**
3. Clear your browser cache

Then choose *Add card* in your dashboard and search for *Radial Flow Card*.

### Wallbox with state of charge

A consumer can additionally get a state of charge sensor, typically
the car at the wallbox. The outer ring still shows the power, the
state of charge is added as its own indicator — either as a horizontal battery with
the percentage inside the node (left, `soc_display: battery`) or as an inner ring that
is closed at 100 %, with the percentage inside the circle (right, `soc_display: ring`). The color can be set with
`soc_color`. [`examples/wallbox-soc.yaml`](https://github.com/Kohle93/radial-flow-card/blob/main/examples/wallbox-soc.yaml)

<img src="https://raw.githubusercontent.com/Kohle93/radial-flow-card/main/docs/images/example-soc-battery.png" width="300" alt="State of charge as a battery icon in the node"> <img src="https://raw.githubusercontent.com/Kohle93/radial-flow-card/main/docs/images/example-soc-ring.png" width="300" alt="State of charge as an inner ring">

```yaml
individual:
  - entity: sensor.wallbox_power
    name: Wallbox
    icon: mdi:car-electric
    max_power: 11000
    state_of_charge: sensor.car_state_of_charge
    soc_display: ring        # or battery (default) or none
    soc_color: "#4cb5e0"
```

If the sensor is `unavailable` or `unknown` (car not connected), the
indicator is hidden and the icon is shown at full size again.

If the state of charge should only be shown while charging, add a second sensor
that reports whether charging is in progress:

```yaml
    charging_entity: binary_sensor.wallbox_charging
    # optional, if the sensor reports text:
    # charging_state: "Charging, Laden"
```

Without `charging_state`, `on`, `true`, `charging`, `laden`, `lädt`, `ladend`,
`active`, `aktiv` and any number above 0 count as "charging" — so a `binary_sensor` or
a charging power sensor work right away. With `charging_state` only the states
listed there count (comma-separated or as a list, case-insensitive).
Without `charging_entity` the state of charge is always visible.

## Configuration editor

The editor is built exactly like the ones of the
[Status Summary Card](https://github.com/Kohle93/Status-Summary-Card), the
[Trash Card Plus](https://github.com/Kohle93/Trash-Card-Plus) and the
[EV Charge Card](https://github.com/Kohle93/EV-Charge-Card): tab bar at the top,
a short introduction per tab and collapsible groups with icons. It uses the
components of the built-in cards, i.e. `ha-entity-picker`, icon and color pickers
and the standard dialog for actions.

| Tab | Content |
|---|---|
| Nodes | List of all nodes (PV, home, battery, grid, consumers) with sorting, removing and a separate edit page with live preview |
| Display | Title, weather, center, nodes & ring |
| Animation | Dots & tail, speed by power |
| Values | Number format, appearance at 0 W |
| Design | Accent color, card – background & transparency, card – border, shape & spacing, text |

On the edit page of a node, the fields are grouped into sensor, name/icon/color,
values & ring, state of charge, behavior, additional info and actions. Values
that match the default are not written to the YAML.

### Weather

With a weather entity, the current temperature and a small icon for the condition
(sun, clouds, rain, snow, thunderstorm, fog, wind …) appear in the top corner. By default the
weather sits in the corner **opposite the title**: title left or centered → weather right,
title right → weather left, no title → right.
`weather_position` lets you fix the side. At night (according to `sun.sun`)
the sun turns into a moon. Tapping opens the weather details by default.

```yaml
weather_entity: weather.forecast_home
weather_temperature_entity: sensor.outdoor_temperature   # optional, e.g. your own outdoor sensor
weather_position: auto        # auto, left, right
weather_show_condition: true  # "Partly cloudy" below the temperature
```

| Option | Type | Default | Meaning |
|---|---|---|---|
| `weather_entity` | string | – | Weather entity (`weather.*`), provides condition and temperature |
| `weather_temperature_entity` | string | – | Own temperature sensor instead of the weather entity's temperature |
| `weather_position` | string | `auto` | `auto` (opposite the title), `left`, `right` |
| `weather_size` | number | `16` | Font size of the temperature in px, the icon scales along |
| `weather_decimals` | number | `0` | Decimals of the temperature |
| `weather_icon_style` | string | `color` | `color` (colored icons) or `mono` (MDI icons in text color) |
| `weather_animation` | bool | `true` | Subtly animate the colored icons (rain falls, sun rotates …) |
| `weather_show_condition` | bool | `false` | Condition as text below the temperature |
| `weather_tap_action` | action | `more-info` | Action when tapping the weather |

the same keys. In the editor under *Design*: accent color, *card – background &

be copied 1:1 between the cards. The old keys up to v5.2 (`bg_mode`,
`bg_opacity`, `blur`, `border_mode`, `shadow`, `radius` …) are still
understood and renamed automatically when editing.

| Option | Type | Default | Meaning |
|---|---|---|---|
| `accent_color` | string \| [r,g,b] | theme accent | Color for `tinted`, `accent` and the accent border |
| `card_bg_mode` | string | `theme` | `theme` (theme background), `tinted` (theme + tint), `accent` (full accent color), `custom` (custom color), `none` (transparent) |
| `card_bg_color` | string \| [r,g,b] | – | Color for `card_bg_mode: custom` |
| `card_bg_opacity` | number | `100` | Opacity of the card in %; for `tinted` the strength of the tint |
| `card_bg_gradient` | bool | `false` | Gradient for `tinted`, `accent` and `custom` |
| `card_blur` | number | `0` | Blur behind the card in px (glass effect) |
| `card_border_mode` | string | `theme` | `theme` (like theme), `none`, `accent`, `custom` |
| `card_border_color` | string \| [r,g,b] | – | Color for `card_border_mode: custom` |
| `card_border_width` | number | `1` | Border width in px for `accent`/`custom` |
| `card_shadow` | string | `theme` | `theme`, `none`, `soft`, `strong` |
| `card_radius` | number | theme | Corner radius in px |
| `padding` | number | `8` | Padding of the card in px |

Applies to `solar`, `grid`, `battery`, `home` and every entry under `individual`.

| Option | Type | Meaning |
|---|---|---|
| `entity` | string \| object | Combined sensor or a pair of sensors |
| `invert` | bool | Invert the sign |
| `name` | string | Display name |
| `icon` | string | MDI icon or `rf:` icon |
| `color` | string \| [r,g,b] | Color of ring and dots |
| `unit` | string | `W`, `kW` or free text; empty = automatic switching |
| `decimals` | number | Decimals for this node |
| `max_power` | number | Maximum power for the partial ring; empty = full circle |
| `ring_source` | string | `battery` only: `soc` (default) or `power` |
| `state_of_charge` | string | `battery` and `individual`: state of charge sensor in % |
| `soc_display` | string | `individual` only: `battery` (default), `ring` (with percentage inside the circle) or `none` |
| `soc_color` | string \| [r,g,b] | `individual` only: color of the state of charge indicator, default `#5cc47a` |
| `charging_entity` | string | `individual` only: only show the state of charge while this sensor reports "charging" |
| `charging_state` | string \| list | `individual` only: states that count as "charging"; empty = automatic |
| `subtract_from_home` | bool | `individual` only: subtract from the home consumption, on by default |
| `subtract_individual` | bool | `home` only: master switch for all consumers |
| `secondary_entity` | string | Additional sensor in the third line |
| `secondary_unit` | string | Unit for it |
| `note` | string | Fixed additional text |
| `tap_action` | action | Default `more-info` |
| `hold_action` | action | Default `none`, triggers after 500 ms |
| `double_tap_action` | action | Default `none` |

Supported actions: `more-info`, `navigate`, `url`, `toggle`, `call-service`,
`perform-action`, `assist`, `fire-dom-event`, `none`.

## Sensors and signs

Positive means flow towards the hub: grid import, battery discharge.
Negative means flow outwards: grid export, charging. If your sensor doesn't match,
use `invert: true`. Sensors in kW or MW are normalized to watts automatically.

Alternatively two separate sensors instead of one combined sensor:

```yaml
grid:
  entity:
    consumption: sensor.grid_import
    production: sensor.grid_export

battery:
  entity:
    discharge: sensor.battery_discharge_power
    charge: sensor.battery_charge_power
```

`consumption` and `discharge` count towards the hub, `production` and `charge`
away from it. Both notations work for both nodes.

Without `home.entity` the home consumption is calculated as a balance:
`PV + grid import + discharge − grid export − charge`. All consumers
with `subtract_from_home` enabled are subtracted from that.

## How the animation works

Exactly one dot with a tail runs per line. First the generation's dot runs
from the node to the center; only when it has arrived do all other dots start
simultaneously inwards or outwards. Then the cycle starts again.

Movement is driven by the card's own timer, not by SMIL. Every line keeps a
progress from 0 to 1 that grows by `dt / duration` per frame. A new sensor value
only changes this step size, never the position — a running dot therefore gets
faster or slower instead of restarting. The timer pauses when the
tab goes to the background.

The duration is mapped linearly from `min_expected_power` … `max_expected_power`
to `max_flow_rate` … `min_flow_rate` and divided by `speed`.

## Size of ring and nodes

`ring_radius` and `node_size` are applied directly and are visible over the whole
range — no hidden recalculation discards the configured values anymore.
The only limit for the node size is pure geometry: neighboring nodes must not
touch, calculated from the actual angular distance on the ring.

If the chosen size no longer fits into the 1000-unit base area with many nodes or long names,
the drawing area grows instead of shrinking the ring or the nodes
on its own. Ring and nodes keep exactly the ratio that was configured —
if in doubt, only the whole graphic is shown slightly smaller.

## Behavior at 0 W

Nodes keep their color and position, only the dots on the line disappear.
The ring background in the node color with reduced opacity lies underneath,
so a node stays colored even without power.

## Limitations

- Sensible up to about twelve nodes, beyond that the ring gets too tight
- A very long title can collide with the label of a node at the top,
  because the title sits on top of the graphic instead of pushing it
  down — short, concise titles reliably avoid this
- In the editor the preview is rebuilt on every change; in normal operation
  only attributes are updated
